# React 状态：用一份事实驱动多个界面

这是一篇 AI 辅助整理的技术学习草稿，供作者审阅后补充真实实践。它不代表作者已经完成相关项目、实验或论文复现。

## 要解决的问题
状态应保存不能从其他数据计算出的事实。筛选结果、选中项详情和结果数量如果都另存一份，很容易在更新时不一致。组件可以拆分，但数据来源与更新方向必须保持清楚。

## 一个可操作的思考示例
在世界列表中保存 query 与 selectedId，从目录计算匹配项，再按 ID 读取详情。输入变化时检查选中项是否仍存在；异步加载使用取消信号，避免旧请求覆盖新结果。打开阅读层时保持背景目录的尺寸规范。

## 容易忽略的边界
用同一索引指代多个列表会导致筛选后打开错误内容。把响应结果直接写入多个状态也会增加同步成本。过度 memo 不能修复数据模型错误。

## 如何确认理解与实现
验证快速输入、空结果、返回目录和加载失败。每个交互都应打开正确 ID 的内容，页面不因异步完成而突然改版。
