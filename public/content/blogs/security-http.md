# HTTP 的安全边界：请求、身份与状态

这是一篇 AI 辅助整理的技术学习草稿，供作者审阅后补充真实实践。它不代表作者已经完成相关项目、实验或论文复现。

## 要解决的问题
HTTP 方法、状态码、头部与消息体表达一次交互。认证回答“是谁”，授权回答“能做什么”；二者不能用一个登录状态替代。TLS 保护传输过程，但不会修复应用内部的错误权限判断。

## 一个可操作的思考示例
为本地 API 列出访客、普通用户与管理员三类身份，在相同资源上比较读写权限。错误信息不应泄漏敏感字段；缓存规则要考虑私人响应，不能把带身份的数据当作公开静态文件。

## 容易忽略的边界
CORS 是浏览器对跨源读取的约束，不是服务端身份校验。隐藏按钮也不是权限机制。状态码正常只能说明请求处理完成，不能代表业务权限正确。

## 如何确认理解与实现
分别检查未登录访问、越权访问、缓存行为和错误响应。每条测试写清资源、身份与预期结果，而不是只写“安全测试通过”。
