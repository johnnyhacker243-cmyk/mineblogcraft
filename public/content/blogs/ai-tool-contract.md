# Tool Calling：先定义契约，再让模型选择工具

这是一篇 AI 辅助整理的技术学习草稿，供作者审阅后补充真实实践。它不代表作者已经完成相关项目、实验或论文复现。

## 要解决的问题
工具调用是结构化请求，不是把模型输出直接交给终端。参数类型、必填字段、枚举、返回格式和权限范围共同构成工具契约。模型负责提出调用，程序负责验证和执行，两层不能混在一起。

## 一个可操作的思考示例
一个 searchWiki 工具只接收 query 与 limit，返回 nodeId、title、snippet 和 source。未知字段应拒绝；limit 要有上限。检索不允许顺带修改节点，写操作需要另一个明确入口，并记录实际执行结果。

## 容易忽略的边界
模型可能产生不存在的工具名或不合法参数。重试要有上限，工具返回应明确区分“零结果”和“服务不可用”。外部内容不能要求系统提升权限。

## 如何确认理解与实现
用缺少 query、负数 limit、未知工具名和超时分别测试。确认不会越界执行，错误能被解释，最终答案只描述确实完成的动作。
