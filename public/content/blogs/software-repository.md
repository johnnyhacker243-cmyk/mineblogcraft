# Repository：让内容存储与游戏界面分离

这是一篇 AI 辅助整理的技术学习草稿，供作者审阅后补充真实实践。它不代表作者已经完成相关项目、实验或论文复现。

## 要解决的问题
Repository 封装数据获取边界，页面使用稳定的方法读取领域对象。它不是为了增加层数，而是让 JSON、API 或数据库变化时不影响 UI 组件。检索评分则属于独立服务，不应与文件读取耦合。

## 一个可操作的思考示例
目录读取只返回标题、日期、标签与正文路径。点击一本书时才读取正文。Wiki 关系使用内容 ID，在数据层解析标题；未来替换 API 时，只实现相同的 getAllNodes 和 getContent 契约。

## 容易忽略的边界
如果每个组件仍然直接导入 JSON，Repository 就只剩名字。过度通用的万能仓库会隐藏不同模块的实际约束，应保留 Blog、Paper、RSS 的明确语义。

## 如何确认理解与实现
替换一个测试 Repository，确认页面仍能正常加载、搜索和显示错误。检查正文不在主入口重复打包，引用都能定位到同一份元数据。
