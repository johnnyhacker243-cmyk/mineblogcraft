# 静态知识站的架构：少依赖，清边界

这是一篇 AI 辅助整理的技术学习草稿，供作者审阅后补充真实实践。它不代表作者已经完成相关项目、实验或论文复现。

## 要解决的问题
静态站点可以用构建阶段完成内容检查和外部聚合，在浏览器中只读取同域文件。目录、正文、关系和抓取结果分层保存，既能减少运行依赖，也能保留未来接 API 的边界。复杂度应由真实需求驱动。

## 一个可操作的思考示例
一次构建先验证内容，再读取缓存快照生成订阅文件，最后输出前端。需要更新外部信息时，使用带抓取步骤的构建命令。网络失败保留旧快照，报告单个来源的状态，不阻止已有知识被阅读。

## 容易忽略的边界
没有后台并不代表没有数据风险：坏引用、过期状态和不可信链接仍需处理。不要为了未来可能的多人编辑提前引入数据库与权限平台。分布式论文提供思考方法，本站并未实现这些算法。

## 如何确认理解与实现
断网构建仍可完成；更新快照有明确命令；能把来源失效与页面失败区分开；每个模块的数据职责可以用一句话说明。
