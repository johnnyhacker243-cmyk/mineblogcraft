# API 契约：静态 JSON 也需要边界

这是一篇 AI 辅助整理的技术学习草稿，供作者审阅后补充真实实践。它不代表作者已经完成相关项目、实验或论文复现。

## 要解决的问题
接口契约描述输入、输出、错误与兼容性。即使当前只有本地 JSON，字段含义也必须固定：更新时间不等于发布时间，内部 ID 不等于显示标题，空数组不等于加载失败。清晰的契约能减少未来接后端时的改动。

## 一个可操作的思考示例
Repository 返回统一领域模型，页面不关心它来自 JSON 还是 API。Blog 元数据与正文分开读取；RSS sourceId 指向信息源，文章日期允许为空；Research 用 readingMode 表明元数据、笔记或全文。

## 容易忽略的边界
把空字符串当成所有缺失值的替代会使校验失去意义。改字段名时应有版本或迁移说明，不能让组件默默兼容越来越多未定义格式。

## 如何确认理解与实现
用缺字段、重复 ID、坏引用和未知枚举做验证。接口失败应显示可理解的消息，不把网络错误解释成“没有内容”。
